## Overview

NaHaber City Network transforms the platform from a single national news site into a multi-tenant city network (e.g. `canakkale.nahaber.com`). The migration is phased to ensure zero downtime and no disruption to the existing Firebase-based production.

### Phase roadmap

| Phase | Description | Status |
|-------|-------------|--------|
| 0 | Codebase audit | ✅ Done |
| 1 | **PostgreSQL foundation** — Drizzle ORM, schema, seed | ✅ Done |
| 2 | Middleware tenant resolution (hostname → tenantId) | ⏳ Next |
| 3 | Dual-write bridge (Firestore + PG parallel writes) | 🔜 |
| 4 | News read path migration to PG | 🔜 |
| 5 | Cloudflare R2 storage migration | 🔜 |
| 6 | City tenant UI (subdomain layout, city-scoped feed) | 🔜 |
| 7–10 | AI Newsroom multi-tenant, analytics, Firestore sunset | 🔜 |

### File structure

```
src/db/
├── index.ts              # Connection + feature flag helpers

├── schema/
│   ├── index.ts          # Barrel export
│   ├── countries.ts      # Country table (PK: 2-letter code)
│   ├── provinces.ts      # Province/il table (PK: slug, FK → countries)
│   ├── districts.ts      # District/ilçe table (PK: slug, FK → provinces)
│   ├── citySites.ts      # Tenant table (PK: id, FK → provinces)
│   ├── categories.ts     # Category mirror (matches DEFAULT_CATEGORIES)
│   ├── users.ts          # Firebase UID mapping (PK: firebase_uid)
│   ├── news.ts           # Core news table + indexes
│   ├── newsLocations.ts  # News ↔ location join table
│   ├── newsCategories.ts # News ↔ category join table (M:N)
│   └── media.ts          # Media assets (storage_provider agnostic)
└── migrations/           # Generated by drizzle-kit (git-tracked)

drizzle.config.ts          # Drizzle Kit config (uses DATABASE_URL_UNPOOLED)
```

### Feature flags

All default to `false` — **no production behaviour changes** without explicit opt-in.

| Variable | Purpose |
|----------|---------|
| `DATABASE_URL` | Neon pooled connection (runtime) |
| `DATABASE_URL_UNPOOLED` | Neon direct connection (migrations only) |
| `CITY_NETWORK_ENABLED` | Gate for any city-network / PG code paths |
| `POSTGRES_READS_ENABLED` | When true, read from Postgres instead of Firestore |

### npm scripts

| Script | Command |
|--------|---------|
| `npm run db:generate` | Generate migration SQL from schema changes |

| `npm run db:push` | Push schema directly (dev only) |
| `npm run db:studio` | Open Drizzle Studio (GUI) |

## Connecting to Neon

### 1. Create a Neon project

1. Go to [neon.tech](https://neon.tech) and create a project
2. Name: `nahaber` (or `nahaber-city-network`)
3. Region: **EU (Frankfurt)** — closest to both Turkey and Vercel `fra1`
4. Compute: Start with the free tier; scale as needed

### 2. Get connection strings

From the Neon dashboard → Connection Details:

- **Pooled** (for runtime): `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/nahaber?sslmode=require`
- **Direct** (for migrations): `postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/nahaber?sslmode=require` (click "Direct connection")

### 3. Configure environment

```bash
# .env.local (never commit)
DATABASE_URL=postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/nahaber?sslmode=require
DATABASE_URL_UNPOOLED=postgresql://user:pass@ep-xxx.eu-central-1.aws.neon.tech/nahaber?sslmode=require
CITY_NETWORK_ENABLED=false
POSTGRES_READS_ENABLED=false
```

### 4. Push schema & seed

```bash
# Create tables from schema (dev workflow)
npm run db:push

# Seed initial data (Türkiye, Çanakkale, categories)
npm run db:seed

# Or dry-run first:
DRY_RUN=true npm run db:seed

# Verify with Drizzle Studio
npm run db:studio
```

### 5. Production (Vercel)

Add `DATABASE_URL` and `DATABASE_URL_UNPOOLED` to Vercel Environment Variables.
Keep `CITY_NETWORK_ENABLED=false` until Phase 2+ is ready.

## Schema design notes

### news table
- `legacy_firestore_id` — stores original Firestore document ID for migration traceability
- `city_site_id` — FK to city_sites for tenant scoping (nullable for national news)
- City/district fields are denormalized for query performance alongside the normalized `news_locations` join table

### media table
- `storage_provider` enum: `firebase | r2 | external` — supports gradual R2 migration (Phase 5)
- `storage_key` — bucket-relative path, decoupled from public URL

### users table
- PK is `firebase_uid` — Firebase Auth remains the auth layer
- Profile/role data only; no auth credentials stored in PG

## Safety guarantees

1. **No production code paths hit Postgres** unless `CITY_NETWORK_ENABLED=true`
2. **`getDb()` is lazy** — no connection attempt until explicitly called
3. **Drizzle is only imported from `src/db/`** — not wired into any existing pages/API routes
4. **Firebase Auth untouched** — `src/lib/firebase/auth.ts` and middleware CMS guard are unmodified
5. **All 51 Vercel cron jobs continue using Firestore** — no dual-write yet
6. **Next.js build safe** — `src/db/` is tree-shaken; no page/route imports it
